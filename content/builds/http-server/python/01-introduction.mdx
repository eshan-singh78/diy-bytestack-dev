An HTTP server can feel like a large piece of infrastructure. Its essential loop is surprisingly small:

1. listen for a TCP connection;
2. read bytes that describe a request;
3. decide what those bytes mean;
4. send response bytes; and
5. close or reuse the connection.

In this guide, you will implement that loop with Python's standard library. The finished server will
recognize basic HTTP requests, route paths, serve a small file, and return useful errors.

<Why>
Frameworks hide the transport so you can focus on applications. We are going one layer lower—not
because every team needs a server, but because sockets and protocols become concrete when you can
watch their bytes move.
</Why>

## What you will demonstrate

By the end, you should be able to:

- Open a local listening socket and identify where request bytes enter the program.
- Parse an HTTP/1.1 request header block and explain why a single `recv()` may be insufficient.
- Send GET and HEAD responses with the correct body behavior and byte length.
- Serve files from a confined `public/` directory and verify success and error cases.
- Diagnose one failure and make one independently tested change.

## The boundary of our server

We will build a learning-sized HTTP/1.x-style server. It will handle one request per connection and
always respond with `Connection: close`. That keeps connection management visible and lets us focus
on the protocol shape.

This is unencrypted HTTP on a loopback TCP socket. The final build supports HTTP/1.1 GET and HEAD, serves static files, and replies to selected errors. It does **not** implement TLS, HTTP/2, HTTP/3, request-body framing, production-grade limits or hardened parsing. Those are deliberate boundaries, not guarantees of safety.

<Warning>
Do not expose this server to the public internet or use it for untrusted traffic. Production servers
have years of security and interoperability work behind them.
</Warning>

## Simple HTTP server

Create a working directory in a terminal:
```bash title="Terminal"
mkdir bytestack && cd bytestack
```
Create a new file named `index.html` inside the directory using your text editor.
Open `index.html` in your editor and add the following HTML:
```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Server Message</title>
</head>
<body>
    <h1>Hi from the server</h1>
</body>
</html>
```
Save the file. Your basic HTML page is now ready to be served.

Check the interpreter that you will use to run the server:

```bash title="Terminal"
python3 --version
```

Python includes an HTTP server module in its standard library. For a baseline comparison, start it with:

```bash title="Terminal"
python3 -m http.server 8000 --bind 127.0.0.1
```
This starts Python's built-in server, not the one you will write.
This will run the server on port `8000`, so the local address will be
[`http://127.0.0.1:8000`](http://127.0.0.1:8000). 

<TryIt>
Open a second terminal and run:
```bash title="Terminal"
curl -i http://127.0.0.1:8000/index.html
``` 
This includes response headers and body. Observe the server terminal log the request.
</TryIt>

Open `http://127.0.0.1:8000/index.html` in a browser. The server remains active until stopped with **Ctrl+C**. If the command reports an address-in-use error, stop the earlier server before retrying.

<TryIt>
After stopping the first server, change `8000` to `8080` and run the command again. The port is part of an address; changing it means
the server starts listening on a different endpoint.
</TryIt>

### Is that it?
No! You just started an HTTP server, but to build your own HTTP server you need to understand:
- How does it work?
- How did it start? 
- How is it listening to the request?
- How is it going to respond?

The module is implemented in Python. You can inspect the [CPython `http.server` source](https://github.com/python/cpython/blob/d59feb5dbe5395615d06c30a95e6a6a9b7681d4d/Lib/http/server.py#L1280), but you do not need to study it to complete this project. 

<How>
The built-in server delegates to a few distinct pieces:
- Handler: The code uses `SimpleHTTPRequestHandler` which reads each request and decides what to send back.
- TCP socket: The server listens on a TCP socket through `socketserver.TCPServer` which accepts a client connection and gives that connection to a handler.
- `serve_forever()`: The server object runs an accept/handle loop until stopped.

Our implementation will expose the socket calls and protocol bytes instead of hiding them inside the module.
</How>
